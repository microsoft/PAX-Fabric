# PAX Fabric — Data Dictionary

This file lists the columns of the Delta tables that the PAX Fabric pipeline writes. It is a reference for people who need to know what a column holds without reading the code. For deployment and operation see the Setup & Execution Guide; for the code structure see the Internal Module Reference.

**Notation.** Where an example is not available, the cell says `TBD`. Example values are illustrative.

**Conventions used in every table below**

- **Type.** Every column is stored in Delta as `string`. The Power BI templates convert columns to dates, numbers and booleans on load.
- **Column names.** Characters Delta does not allow in a column name (space, `,`, `;`, `{`, `}`, `(`, `)`, `=`, tab, newline) are replaced with `_` when the table is written, so a name such as `License Status` is stored as `License_Status`.
- **Stored values.** Each CSV is read with automatic type detection before its values are stored as text. As a result `true` / `false` are stored in lower case, timestamps as `YYYY-MM-DD HH:MM:SS.000000000Z`, and numbers without trailing zeros (for example `0.5`, `1`). A blank value is stored as NULL when its column holds true/false values, numbers or timestamps, or when every value of that column in the run is blank; otherwise it is stored as empty text.
- **Tables and prefixes.** `AIO_`, `ValueLens_` and `M365_` are the dashboard prefixes (see the Setup Guide, section 14). `CopilotInteractions_Raw`, `CombinedActivityTypes`, `Entra_Users_Raw`, `Agent365` and `Agent365_Status` are shared and never prefixed.
- **De-identification.** "De-identified" in Notes means the column is transformed when `Deidentify` is on (columns listed in `mod18_pax_deidentify.py`, plus the Copilot processor's own token functions).
- **PowerShell match.** In Notes, "Matches the PAX PowerShell CSV column of the same name" means the PowerShell tool (v1.11.16-prerelease) writes the same column name in the same position.
- **Cowork.** There is no separate Cowork table. Cowork activity is identified by the value `Cowork` in the `Environment` column of the Copilot interactions tables.
- **Stub rows.** In the Users tables, a user that appears only in the audit data (not in the Entra directory) gets a stub row: `PersonId`, `PersonId_Normalized` and `UserKey` are set and the other columns are blank. "Blank on stub rows" refers to these rows.
- **Dates.** `InteractionDate`, `ActivityDate`, `WeekStart` and `MonthStart` are written as `YYYY-MM-DD`. `createdDateTime` and `employeeHireDate` (Entra / Users) are written as `DD-MM-YYYY HH:MM:SS`. `Agent365` dates are written as `YYYY-MM-DD HH:MM:SSZ`.

## 1. CopilotInteractions_Raw / CombinedActivityTypes

- **Purpose:** Raw (un-aggregated) Purview audit events. `CopilotInteractions_Raw` holds the Copilot audit events; `CombinedActivityTypes` holds the combined M365 activity events (Exchange, SharePoint, OneDrive, Teams and Copilot) when `Rollup` is off. Both have the same columns. Not read by the dashboard templates in this repository.
- **Grain:** One row per Purview audit record.
- **Write behavior:** Replaces the collected `CreationDate` range, then appends (`delete_date_append`).
- **Parameters that change the table:** `Deidentify`, `ActivityTypes` / `RecordTypes` / `UserIds` filters (change which records are written), `ExplodeArrays` / `ExplodeDeep` (write a wider, flattened column set instead of the columns below). See the Setup Guide for when each table is produced.
